# R190627 居民问题集审查说明

## 结论

原 42 题不能直接作为本轮统一验收题。它覆盖的工具很多，但部分问题更像开发者写给模型的指标清单，而不像居民真的会问的问题；新增 Aurora 题又把重点放在“两种模型是否一致”和误差排名上，没有完整测试老师要求的“区域发现—局地追踪”工作流。

现以 `R19062708588472` 为唯一主 study case，重新审查并形成 42 题。可执行的权威问题源是 [resident_questions_42.json](../data/evaluation/resident_questions_42.json)，两个 42 题测试脚本都从该文件读取，不再各自保存一份容易漂移的题目副本。

## 审计发现

1. **旧问题过度规定答案。** 后期版本在一题中列出大量固定指标、阈值、图表和算法。这样测试的主要是模型能否照抄清单，不是 Agent 能否理解普通用户目标并自主选择合适证据。
2. **两个模型的关系设计偏了。** 旧 Q39 直接问局地 VIL 与大尺度环境“是否一致”，但 Aurora 的 6—24 小时区域环境和 CasCast 的 1—2 小时局地演变既不在同一尺度，也不应作简单数值一致性比较。
3. **缺少中间定位环节。** 旧题从 Aurora 环境预测直接跳到局地分析，没有单独验收“候选区域与时段 → 匹配可用连续观测 → 提取此前一小时”这两个关键步骤。
4. **案例发生漂移。** 旧 Q40 指向 Chatsworth，早期材料又用 Springfield 举例；但当前缓存和演示主线是 `R19062708588472`。这会让统一测试主动进入无缓存路径，无法满足 30 秒约束。
5. **CasCast 时效要求过强。** 老师已明确 CasCast 主要看未来 1—2 小时，三小时结果已经很不稳定。新版不再把三小时精细预测当作主能力，第二小时也只要求趋势和边界说明。
6. **图片被当成前置条件。** 新问题集中保留“不上传图片也能询问能力、指定时间地点、检查或主动准备数据”的验收入口。
7. **旧验收尺度太严。** 新审查只要求回答用户目标、证据路径正确、边界诚实。轻微天气学措辞不够专业、没有列完所有可计算指标，不触发重写。

## 42 题结构

| 范围 | 用户目标 | 主要证据路径 | 执行关系 |
|---|---|---|---|
| Q01—Q06 | 看懂一张当前天气图 | 单帧 SEVIR 与地理信息 | 可并行 |
| Q07—Q12 | 理解此前一小时、获得一小时短临并验证 | 连续 SEVIR → CasCast → 后续 SEVIR | Q09 在 Q07 后；验证题在预测后 |
| Q13—Q16 | 看懂多种预测和不确定性 | CasCast Ensemble | 预测缓存准备后可并行 |
| Q17—Q24 | 出行建议、时效边界与证据说明 | 短临、集合、历史和实况 | 依赖相关预测结果 |
| Q25—Q32 | 无图片查询、自动数据准备、异常输入和能力边界 | 时间地点解析、目录/缓存、输入校验 | 无关联题可并行；Q30 串行多轮 |
| Q33—Q42 | 老师要求的完整跨尺度 study case | ERA5 → Aurora → 区域/时段 → 此前一小时观测 → CasCast → 后续观测 | 同一会话严格串行 |

## 核心 study case 问题（Q33—Q42）

33. 以2019年6月27日08:58 UTC、事件R19062708588472所在区域为起点，未来6到24小时的大范围天气环境会怎样变化？请先告诉我哪些变化最值得居民留意。
34. 在刚才的大范围预测里，哪些区域和时段最值得进一步查看当地天气？请给出少量候选，并解释为什么值得继续追踪。
35. 请从候选中选择与R19062708588472连续观测相匹配的地点和时间，说明为什么选它，并确认当地是否有此前一小时的可用观测。
36. 把这个地点目标时刻此前一小时的连续观测调出来。过去一小时当地天气是怎样发展到现在的？
37. 根据这段连续观测，未来一到两小时当地最可能怎样变化？请指出重点时间和位置，并说明第二小时只能作多大程度的参考。
38. 结合大范围环境和局地短临来看，当地过程是否正在朝前面提示的值得关注形势发展？请说出支持和不支持这一判断的证据，不要只回答两种结果是否一致。
39. 请用后来实际观测检查刚才的局地判断：哪些发展趋势出现了，哪些没有出现，位置或时间有没有偏差？
40. 请用对应时刻的后续环境资料检查Aurora先前指出的区域和时段是否仍值得关注。环境预测和局地短临要分别验证，不要混成一个总分。
41. 如果大范围环境看起来值得警惕，但当地短临没有明显发展，或者反过来，我应该怎样理解？这会怎样改变你的提醒程度？
42. 请把R19062708588472这次案例按时间顺序讲成一个完整故事：先发现了什么区域信号，随后当地观测和短临看到了什么，后来实况如何验证。最后告诉附近居民最有用的一条结论和仍需留意的不确定性。

这十题不再要求 Aurora 和 CasCast 给出“相同答案”。Aurora 的职责是发现值得进一步查看的区域和时段；CasCast 的职责是利用已定位地区此前一小时的连续观测，追踪未来一到两小时的局地演变。二者最后通过证据链综合解释，并分别接受对应后续观测的验证。

## 结果审查规则

一次回答在以下条件下即可接受：

- 回答了问题中的时间、地点或生活决策目标；
- 使用的数据与问题尺度匹配；
- 没有把候选区域说成必然发生的灾害；
- 对缺失数据和较远时效给出诚实边界。

以下情况才判为失败并进入根因排查：答非所问、调用了错误尺度的模型、编造数据、丢失串行上下文，或遗漏问题的核心目标。不要因为没有列全专业指标或措辞不够像天气学论文而要求 LLM 重写。
